GsChecker

GsChecker es un bot de Discord que permite consultar información de personajes de Warmane (WotLK). Con un simple comando podés ver GearScore, progresión de raids, logros, specs activas, enchants/gemas faltantes y estadísticas de DPS desde UwU Logs.

El bot combina datos de la Armory de Warmane con los de uwu-logs.xyz para darte un resumen completo del personaje en un solo embed.

💡 Todos los comandos usan el prefijo /. Los nombres de personaje no distinguen mayúsculas; el bot los normaliza automáticamente.

📖Comandos

/personaje <nombre> [reino]
Alias: /p

Muestra un resumen completo del personaje: GearScore, nivel/raza/clase, spec activa, guild, progresión ICC, Ruby Sanctum y enchants/gemas faltantes.

ParámetroTipoDescripción
nombre requerido Nombre del personaje.
reino opcional Reino del personaje. Si no se envía, usa Lordaeron. Reinos soportados en estado actual: Lordaeron, Icecrown, Blackrock, Onyxia, Frostmourne.

Ejemplo

/personaje Muzzi # o equivalentemente: /p Muzzi # con reino explícito: /p Muzzi Icecrown

¿Qué incluye la respuesta?

  • GearScore – calculado localmente con la tabla de GS de WotLK.
  • Level · Race · Class – datos básicos del personaje.
  • Spec – la spec activa aparece en negrita; la inactiva, en texto normal.
  • Guild – nombre de la guild o "Sin guild".
  • Armory / Uwulogs – links directos al perfil.
  • Icecrown Citadel – tabla de kills por boss y dificultad (10N/10H/25N/25H). Para Marrowgar y Deathwhisper los datos de 10H/25N/25H se obtienen de UwU Logs (muestra una animación ⌛/⏳ mientras carga).
  • Ruby Sanctum – kills de Halion en todas las dificultades (por logros).
  • Enchants / Gems – slots sin encantar o sin gema (solo aparece si hay faltantes).

Vista de la tabla ICC

✅ = al menos 1 kill · ⚠️ = parcial (algunos bosses con kill) · ❌ = sin kills
/dps <nombre> [spec]

Muestra una tabla con el DPS máximo y promedio del personaje por boss y dificultad, obtenidos de uwu-logs.xyz.

Los bosses incluidos son: Marrowgar, Saurfang, Festergut, Rotface, Putricide y Lich King.

ParámetroTipoDescripción
nombre requerido Nombre del personaje en Lordaeron (alcance actual de /dps).
spec opcional Filtra los logs por especificación. Ver la lista completa de keywords en la sección Filtro por spec.

Ejemplos

/dps Muzzi # todos los specs /dps Muzzi fury # solo logs de Fury Warrior /dps Muzzi udk # solo logs de Unholy DK /dps Muzzi frost # Frost DK spec 2 o Frost Mage spec 3

/ptoc <nombre>

Muestra los logros de Trial of the Crusader (ToC) del personaje en las cuatro dificultades (10N, 10H, 25N, 25H). Usa los logros "Call of the Crusade" y "Call of the Grand Crusade".

ParámetroTipoDescripción
nombre requerido Nombre del personaje en Lordaeron (alcance actual de /ptoc).

Ejemplo

/ptoc Muzzi

Vista de la tabla ToC

Boss | ✅10N | ❌10H | ✅25N | ❌25H -------------------------------------------------------- Trial of the Crusader | ✅ | ❌ | ✅ | ❌
/ping

Responde con la latencia actual del bot en milisegundos.

/ping Pong! Latencia: 42ms

🎯Filtro por spec (comando /dps)

El parámetro spec acepta las siguientes keywords (no distingue mayúsculas):

bdk, blood, fdk, frost, udk, unholy
Warrior
arms, fury
Paladin
holy, prot, protection, ret, retribution
Hunter
bm, beastmastery, beast, mm, marks, marksmanship, sv, survival
Rogue
assassination, mut, mutilate, combat, sub, subtlety
Priest
disc, discipline, holy, spriest, shadow
Shaman
ele, elemental, enh, enhancement, resto, restoration
Mage
arcane, fire, frost
Warlock
affli, affliction, demo, demonology, destro, destruction, dest
Druid
boomkin, balance, feral, rdruid, resto
⚠️ frost es compartida: en DK corresponde a Frost (spec 2) y en Mage a Frost (spec 3). El bot busca en ambas y combina los resultados.

📌Notas y limitaciones

Fuentes de datos

  • GearScore se calcula asignando un número a cada item según su nivel y rareza.
  • Progresión ICC / RS viene de las Statistics y Achievements de la Armory de Warmane.
  • ⚠️ Marrowgar y Deathwhisper 10H/25N/25H usan UwU Logs directamente porque la Armory no los registra correctamente. Si no hay raids recientes subidas a uwu-logs, el bot puede mostrar información incorrecta o vacía para estos bosses.
  • ⚠️ DPS y datos de /dps provienen exclusivamente de uwu-logs.xyz. Si el personaje no tiene logs subidos o las raids no fueron registradas, el comando puede retornar datos vacíos o erróneos.
  • ToC se detecta por logros de Armory; si el personaje no tiene el logro global, aparece ❌ aunque haya matado bosses individuales.

Cache

Para evitar sobrecargar las APIs, los datos se cachean en memoria por un tiempo determinado. Si acabas de equiparte o hacer un boss, puede haber un retraso de hasta:

DatoTTL
Summary / Gear2 minutos
Logros / ICC kills3 – 5 minutos
DPS (uwu-logs)3 minutos

Servidor

/personaje y /p permiten elegir reino (por defecto Lordaeron).
/dps y /ptoc actualmente operan sobre Lordaeron.
⚠️ Algunas respuestas de Armory pueden variar por reino (especialmente talentos/specs), y hay rate-limit intermitente. Si un dato no aparece al instante, reintentar luego de unos segundos.

Arquitectura general

El bot corre como proceso único (Python). Los slash commands están en src/controller/commands.py y ejecutan tareas concurrentes con asyncio + ThreadPoolExecutor para consultas a Warmane/UwU.

Usuario en Discord
→
discord.py command
→
asyncio gather()
→
Warmane Armory API
→
Cache en memoria (TTL)
→
uwu-logs.xyz API

Módulos principales

main.py
  • Boot del bot + sync slash commands
  • Lock de proceso (/tmp)
  • Carga de entorno y DB init
src/controller/commands.py
  • Implementación de /personaje, /p, /dps, /ptoc, /ping
  • Orquestación async de fuentes externas
  • Cache command-level y serialización de payload
src/functions/warmane.py
  • Summary, achievements, stats y guild rank
  • Fallbacks API/HTML de Armory
  • Cache en memoria con TTL
src/functions/uwu.py
  • Integración uwu-logs.xyz
  • Resumen DPS por boss/mode
  • Fallbacks para kills especiales
profile_scraper.py
  • Scraping de página de perfil
  • Extracción de gear y specs
  • Detección de enchants/gemas faltantes
src/db/postgres.py
  • Cache externo (external_api_cache)
  • Lectura/escritura de payloads JSON
  • TTL por fuente
gearscore.py
  • Cálculo de GearScore local
  • Lookup de item IDs contra tabla JSON
static/
  • GS.json – tabla de GS por item
  • item_slot_cache.json
  • item_sockets_cache.json
  • raid_items_extra.json

Variables de entorno requeridas

DISCORD_TOKEN=tu_token_aqui # Opcional para cache externo DATABASE_URL=postgresql://user:pass@host:5432/db # (también soporta POSTGRES_URL o variables PG*)

Correr localmente

# Clonar e instalar dependencias git clone https://github.com/joaquinmuzzi/GsChecker cd GsChecker pip install -r requirements.txt # Crear .env con tu token echo "DISCORD_TOKEN=tu_token" > .env # Iniciar el bot python main.py
⚠️ No subas el archivo .env al repo. En producción (Railway), configurá la variable DISCORD_TOKEN desde el dashboard de variables de entorno.
